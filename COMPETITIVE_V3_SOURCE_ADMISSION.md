`vedtektsfestetFormaal` to JSON, CSV, Excel and API. Thus they are not inherently
dependent on an extra live request. This does NOT prove that Builderr's specific
supplied frozen file contains them. Documentation examples explicitly are not
real entities and are NOT positive company coverage evidence.

Access/rights: public register under NLOD2.0 with source attribution; no protected
roles/person endpoints. Frozen input bytes plus exact organisation-number row
binding support publication. CSV quoting/multiline parsing remains existing
bounded parser behavior. Text is a registered declaration, not independent
evidence of actual operations, revenue, jobs, dated events or current activity.
No new effective date is derived. Applicable snapshot/cutoff must be preserved.

Observed opportunity: old entity values contain activity100/100 and purpose95/100,
but identity raw bytes/receipts are unavailable. The public universe has neither
field. Genuine new coverage is NOT established. Implementation accepts only the
literal supplied columns, with exact locators and versioned normalization.
Zero extra network requests. Benchmark actual serialization overhead separately.
Refresh compares authenticated old/current source rows; missing/incomparable
values do not generate a deletion or invented business change.

Decision: implement/test conditional projection locally; do not publish a
competitive revision until the actual representative source and coverage gate
is satisfied. Do not download today's entire registry and call it the historical
official snapshot. Next source prerequisite is an authoritative CSV containing
these fields, or an explicitly authorized sampling program and a separately
labelled current-data experiment. No such requests are authorized by this work.
